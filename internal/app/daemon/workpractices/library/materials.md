# 管理共享资料和交付

先判断资料的用途与权威位置。实现规范、代码事实和随代码演进的说明优先进入仓库；工作项、缺陷和代码评审进入项目采用的 issue／PR 系统；面向人的长期讨论和说明可放飞书文档，结构化登记可放表格。不要让几处同时成为同一事实的权威来源。

正式资料复用已经登记的稳定入口。更新已有文档的适当部分，不在每次汇报时建立新的同名文档。引用代码、需求和验收结论时保留实际版本；当前源链接不等于某个历史版本。

临时文件保留在工作的临时位置；决定交付后，将需要长期保存的内容登记并保存到正式位置。保存失败或媒体不完整时明确说明，不能只发一个临时文件路径就宣称长期交付已经完成。

对人只交付必要结论、待决定的问题和成果入口。完整资料应当可继续查看，但不要求人阅读所有 Agent 产物。清理临时资源前检查活跃引用；归档项目不等于永久删除资料。
