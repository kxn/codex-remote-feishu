# 协作后的集成检查

先检查每项工作实际交付的内容和版本，再整合到共同结果。独立任务可以并行；存在先后依赖的部分应先约定接口和数据归属。Agent 按需要管理分支和工作目录，不把日常 Git 操作交给用户。

保留他人的未提交修改；不要用覆盖、重置或大面积兼容分支掩盖冲突。解决冲突时检查最终行为是否仍满足原要求，而不只是让文件可以编译。

沿真实入口验证新功能：谁接收输入、谁保存状态、谁执行、谁确认结果、出错后谁继续处理。没有接入生产调用的组件不能算作完成的用户功能。核对边界上的身份、版本、重试和迟到事件。

集成以后运行与风险相符的检查，再按项目约定提交、评审或交付。代码仓库和 PR 保存实现事实；飞书只保存必要说明和稳定入口，不另造一份互相矛盾的代码完成状态。
