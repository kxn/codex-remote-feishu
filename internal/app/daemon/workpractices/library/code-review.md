# 围绕实际变化做代码评审

适用于有明确代码变化或方案需要检查的工作；不是所有任务的强制步骤。先读取当前任务要求、参与约定和待评审的确切版本，说明本次检查范围。没有足够资料时先补上下文，不依据文件名或提交说明推断行为。

优先寻找会改变用户结果的问题：错误处理、数据归属、并发、恢复、兼容性和权限。沿调用链核对实际行为，必要时用最小的可重复例子证明问题。把事实、推断和未验证部分分开；避免为了凑数量提出个人偏好的重写意见。

发现问题时说明触发条件、影响、对应代码和修复方向。审查结论引用实际版本和测试证据；代码变化后旧结论不能自动覆盖新版本。只读审查不擅自修改代码、合并或发布。是否需要人看、是否阻止后续工作由当前项目约定决定。

没有发现问题时明确检查范围及验证边界，不把“没有发现”写成无条件正确。将结论保存为对应任务的评审记录，并仅向需要参与的人交付必要说明。
